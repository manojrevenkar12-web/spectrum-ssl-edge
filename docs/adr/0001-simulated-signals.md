# 1. Simulated signals, domains as distributions

Status: accepted

## Context

Recorded RF datasets with the impairments we need to control (multipath, receiver hardware, symbol
rate, bursts and dropouts) are either not public, licensed for research only, or fixed: RadioML 2016
and 2018 vary SNR and a few channel effects, but one cannot ask them for "the same signals through a
cheaper receiver". The questions here are about *shift*, so the shift has to be a dial.

## Decision

Generate complex baseband with a documented signal path (`src/sse/signals`): RRC-shaped linear
modulations, GFSK, AM, FM and a small OFDM; a Rapp power amplifier, a tapped-delay-line channel with a
Rician first tap, receiver LO offset and phase noise, thermal noise, IQ imbalance and DC offset, then
what the recorder kept (bursts, dropped samples, short captures). A *domain* is a set of parameter
ranges; each window draws its own parameters, so a domain is a distribution, not a setting.

## Consequences

- Every effect is unit-tested against its definition (RRC is Nyquist, SNR measured equals SNR asked,
  CFO appears as a spectral shift, the PA compresses peaks and not phase, ...).
- Results transfer to recorded data only as far as the simulator is right. The report says so; the
  first step with real recordings would be to fit domain ranges to them and re-run the same questions.
- Novel classes for the open-set test are generated by the same code, so "novel" means a different
  waveform, not a different recording setup.
